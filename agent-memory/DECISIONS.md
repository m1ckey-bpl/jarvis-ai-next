# DECISIONS — jarvis-ai-next

All significant architecture and design decisions with rationale.

---

## D1 — JSON file store for runtime memory (not SQLite)
**Date:** 2026-10-17
**Decision:** Use JSONEncoder/Decoder to a flat file in Application Support for MemoryStore.
**Rationale:** SQLite requires C bindings which add Swift Package Manager complexity. A JSON store is sufficient for MVP memory volumes (< 10,000 records), easier to debug, and can be upgraded to SQLite later without changing the MemoryStore interface.
**Trade-off:** No indexed queries; keyword search is linear scan. Acceptable for MVP.

## D2 — On-device voice (AVSpeechSynthesizer + SFSpeechRecognizer)
**Date:** 2026-10-17
**Decision:** Use AVSpeechSynthesizer for speech output and SFSpeechRecognizer for speech input. Do NOT use Gemini audio input/output.
**Rationale:** Both are free, on-device, work offline, have no quota. Gemini Live Audio API is not freely available on all accounts and would add significant cost and complexity.
**Trade-off:** Voice quality is system TTS rather than neural audio. Acceptable; system voices are high quality on iOS 17+.

## D3 — Gemini Flash as primary provider, Groq as fallback
**Date:** 2026-10-17
**Decision:** Default provider is Gemini 1.5 Flash (or 2.0 Flash if available). Fallback is Groq with Llama-3.1-8b-instant.
**Rationale:** Gemini Flash is the most capable free model with generous quotas (15 RPM, 1M TPM/day). Groq is the fastest free fallback with no credit card required. Both use simple REST APIs.
**Trade-off:** Gemini Pro (more capable) requires billing. Documented in FREE_TIER_POLICY.md.

## D4 — iOS 17.0 minimum deployment target
**Date:** 2026-10-17
**Decision:** Minimum iOS 17.0.
**Rationale:** Enables `.glassEffect()` modifier (iOS 17+), `Observable` macro, newer SwiftUI APIs. Covers ~90%+ of active iPhones as of 2026.

## D5 — Monorepo (ios + backend + memory in one repo)
**Date:** 2026-10-17
**Decision:** Single GitHub repository contains iOS app, backend, scripts, docs, and engineering memory.
**Rationale:** Simplifies CI/CD, keeps engineering memory co-located with code, single source of truth, one clone for the agent.

## D6 — No external Swift package dependencies
**Date:** 2026-10-17
**Decision:** JarvisCore has zero external Swift Package dependencies.
**Rationale:** Reduces build time, eliminates supply-chain risk, simplifies Xcode project generation, avoids package resolution network calls in CI.
**Trade-off:** Must implement utilities (Keychain wrapper, HTTP client) from scratch. These are simple and well-documented.

## D7 — Backend is optional (iOS-first)
**Date:** 2026-10-17
**Decision:** The iOS app makes direct Gemini/Groq API calls from the device. The FastAPI backend exists for server-side features but is not required for core functionality.
**Rationale:** Simplifies the zero-cost constraint (no always-on server needed), reduces latency, works offline for cached features.
**Trade-off:** API key stored in iOS Keychain instead of server. The key never leaves the device (not committed to repo).

## D8 — Unsigned IPA via GitHub Actions macos-14
**Date:** 2026-10-17
**Decision:** Produce unsigned IPA using `xcodebuild CODE_SIGNING_ALLOWED=NO` on a GitHub Actions macos-14 runner.
**Rationale:** Free public repo runners. Xcode 15.4 available. macOS-14 supports iOS 17 SDK. User handles signing via AltStore/Sideloadly.

## D9 — pbxproj regenerated by Python script
**Date:** 2026-10-17
**Decision:** `scripts/generate_xcode_project.py` regenerates `project.pbxproj` from a known-good template whenever source files change.
**Rationale:** Hand-editing pbxproj is error-prone. A generator ensures consistency, catches stale file references, and enables automated CI checks.
